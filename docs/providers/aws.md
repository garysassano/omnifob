# AWS IAM Identity Center

## Flow

`fob login` signs in the way `aws sso login` does since AWS CLI 2.22.0.

1. `RegisterClient` (name `omnifob`, type `public`, scopes `sso:account:access`). For the browser flow also grant types `authorization_code` and `refresh_token`, the redirect `http://127.0.0.1/oauth/callback` without a port, and the start URL as `issuerUrl`. Registrations are kept per flow at `aws-sso/<integration>/client/<flow>`, apart from the session, and reused until a day before they expire; `fob logout` keeps them, as the AWS CLI does.
2. Browser flow (the default): listen on a free port on `127.0.0.1`, open the consent page (`RegisterClient`'s `authorizationEndpoint`, else the OIDC endpoint the SDK resolves for the region, plus `/authorize`) with `response_type=code`, `client_id`, `redirect_uri`, `state`, `code_challenge_method=S256`, `scopes` and `code_challenge`, wait up to ten minutes for `/oauth/callback`, check `state`, then `CreateToken` with the `authorization_code` grant, the code, the PKCE verifier and the same redirect URI.
3. Device flow (`--device-code`, and on its own when `SSH_CONNECTION`, `SSH_CLIENT`, `SSH_TTY` or `CODESPACES` is set or `/.dockerenv` or `/run/.containerenv` exists): `StartDeviceAuthorization`, show `verificationUriComplete` and the user code, poll `CreateToken`; `AuthorizationPending` keeps polling, `SlowDown` adds five seconds.
4. Store `{start_url, region, access_token, expires_at, refresh_token, client_id, client_secret, client_expires_at}` in the keychain at `aws-sso/<integration>/token`.
5. Before use: refresh with the refresh token when within 15 minutes of expiry, under a file lock per integration (`locks/aws-sso-<integration>.lock` in the state directory), reading the token again once the lock is held. When the refresh fails, the token is used while it is still valid. Once it has expired, or the portal refused it, only the errors `CreateToken` documents as final (`InvalidGrantException`, `ExpiredTokenException`, `InvalidClientException`, `UnauthorizedClientException`, `AccessDeniedException`) delete the session and ask for a new sign-in. Anything else (a network error, a timeout, `SlowDownException`, `InternalServerException`, or another request error such as `InvalidRequestException`) fails the call with "could not renew the sign-in with IAM Identity Center", the cause and a hint to run `fob login` if it persists, and keeps the session for the next try, as the AWS CLI keeps its token cache. `InvalidClientException` and `UnauthorizedClientException` also delete the stored registration of the refused client, so the next sign-in registers again.
6. Discovery: `ListAccounts` then `ListAccountRoles` per account, four at a time. Profile ids `<integration>/<slug(account name)>/<role>`; colliding slugs get `-<account id>`.
7. Credentials: `GetRoleCredentials` → `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `AWS_CREDENTIAL_EXPIRATION`, and `AWS_REGION`/`AWS_DEFAULT_REGION` when `default_region` is set.
8. Console: new role credentials (never the cached ones, which are handed out until five minutes before they expire, and the console session ends with them), sent to the federation endpoint of the credentials' partition in the body of a form POST to `getSigninToken` (`Action`, `Session`, and `SessionDuration` in seconds when a console session length is set), so they stay out of URLs, proxy and access logs, and error messages; then a `login` URL to the console, in `--region` or else the Region exported for the profile when there is one. The destination is `https://<console host>/<service>/home?region=<region>` as granted builds it, with `console` as the service when only a Region is given and the bare console host when neither is; `--service` is the path after the host, taken as given (letters, digits, `-`, `_`, `.` and `/`), without granted's shortcut table. Neither the credentials nor the sign-in token are logged; a refused request reports the HTTP status only. Every Region (from `--region`, `default_region`, a role's `region`, the portal's or the STS Region) must be shaped like one (lowercase words joined by hyphens, ending in a number) before it becomes part of a host name, so a value such as `attacker.example#` cannot send the credentials to another host. The partition comes from the role ARN for chained roles and IAM users' roles, and from the portal's Region (or the IAM user's STS Region) otherwise; a Region from another partition is refused, and so are the isolated partitions (`aws-iso`, `aws-iso-b`, `aws-iso-e`, `aws-iso-f`), which have no public console. With an exported Region the sign-in host and the console are regional (`<region>.signin.aws.amazon.com`, `<region>.signin.amazonaws-us-gov.com`, `<region>.signin.amazonaws.cn`, `<region>.signin.amazonaws-eusc.eu`), except in `us-east-1`, `us-gov-west-1` and `cn-north-1`, which use the unprefixed hosts. Without one, both are unprefixed (`signin.aws.amazon.com`, `signin.amazonaws-us-gov.com`, `signin.amazonaws.cn`). The European Sovereign Cloud has no unprefixed sign-in host (`signin.amazonaws-eusc.eu` does not resolve), so there the sign-in uses the portal's Region, else the partition's first (`eusc-de-east-1.signin.amazonaws-eusc.eu`), and the console opens at `console.amazonaws-eusc.eu`.
9. `fob logout`: the portal's `Logout` ends the session at Identity Center, then the token is deleted. An expired access token is renewed first, since its refresh token stays valid at Identity Center until the portal session ends; if Identity Center refuses the renewal, there is no session left to end. If the renewal fails for another reason, `fob logout` warns that the portal session ends on its own when it expires, and still deletes the token.

`GetRoleCredentials` answers 403 for a while after an account assignment is made; omnifob retries twice (after 1 and 2 seconds) before reporting no access, as granted can.

A 401 from a portal call renews the session once and retries. If the portal refuses the renewed token too, or Identity Center refuses the renewal, the session is deleted (only if it still holds the refused token) and a new sign-in is asked for. A renewal that fails for any other reason keeps the session and reports the error.

The SDK clients are built without `aws-config` (the portal and OIDC calls are unsigned), which keeps dependencies down. `OMNIFOB_AWS_ENDPOINT` sends every AWS call to one URL, the console's `getSigninToken` included (at `<url>/federation`; the returned sign-in URL keeps the real host); the tests in `crates/omnifob-core/tests/aws_sso.rs` point it at a mock.

## Console session length

Without `SessionDuration`, a console session lasts as long as the credentials it was opened with. `--duration` on `fob console`, or `console_duration` on an `aws-sso` integration (for its Identity Center roles) or on an `aws-iam` role, sends one: 15 minutes to 12 hours, and shorter than the role's maximum session duration ("cannot be greater than or equal to"), which for an Identity Center role is the permission set's session duration. omnifob cannot read that maximum, so there is no default, and a refused sign-in names it as the likely cause. The federation endpoint refuses `SessionDuration` for credentials from role chaining and from `GetFederationToken`, so `--duration` is refused before any call for chained roles and for an IAM user's own session, and the integration's `console_duration` is not sent for its chained roles. aws-sso-cli sends `SessionDuration` the same way and leaves it out for chained roles; granted sends none.

## Chained roles

Roles reached from an Identity Center role (`role_arn` with `source_profile` in `~/.aws/config`) are configured under `chained`. omnifob gets the Identity Center role's credentials, then calls STS `AssumeRole` with the configured session name and external ID. AWS limits chained sessions to one hour. `AWS_REGION` is exported only when the role or the integration sets a region; STS is called in the portal's region otherwise. With `mfa_serial`, `AssumeRole` sends the device and a code the user types; the credentials are then cached for the session, and parallel requests for the profile wait for one prompt. `duration` sets the session length, 15 minutes to 1 hour, and `fob exec --ttl` overrides it. `fob console` gets new credentials each time, so a chained role with `mfa_serial` asks for a code each time the console opens.

## The AWS config file

`fob import aws` reads `sso-session` sections, legacy `sso_start_url` profiles and granted's keys from `~/.aws/config`, and writes integrations and chained roles. `fob export aws-config` writes a marked block of profiles that call `fob creds --format credential-process`, so tools that read the AWS config get omnifob's credentials.

## IAM users

`type = "aws-iam"` keeps an IAM user's access key in the keychain at `aws-iam/<integration>/key`, the way aws-vault does, and never hands it out.

- `fob login` asks for the access key ID and secret (or reads both from `--token-stdin`), refuses temporary `ASIA` keys, checks the key with `GetCallerIdentity` and stores it.
- Profiles: `<integration>/<account or account ID>/session` for the user's own session, and `<integration>/<label>/<role>` per entry under `roles`.
- The session comes from `GetSessionToken`, with `SerialNumber` and a typed code when `mfa_serial` is set, lasting `session_duration` (15 minutes to 36 hours, default 8 hours). It is kept at `aws-iam/<integration>/session` and reused until five minutes before it ends; a new one is started under a lock shared by every omnifob process, so parallel commands ask for one code.
- Roles are assumed with the session. That is not role chaining, so their sessions last up to 12 hours (`duration`, default 1 hour, never past the session's end), and the session's MFA satisfies trust policies that require it: one code covers every role.
- Console: session credentials cannot sign in, so the session profile gets a new federated session from `GetFederationToken` with the access key, limited to the user's own permissions by an allow-all policy (as aws-vault does), lasting `session_duration`; that is also the console session's length, since `SessionDuration` cannot be sent with it. Users whose policies require MFA should open the console through a role. A role's console uses new role credentials, which never outlast the user's session. Its `console_duration` sends `SessionDuration`, which the AWS page documents as independent of the credentials' duration for `AssumeRole*` credentials; whether that also holds past the end of the user's `GetSessionToken` session is not stated there and has not been tried live.
