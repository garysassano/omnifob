## 2026-10-07

- "Do all the improvements you deem necessary." Order chosen: WSL persistence, background renewal, revoke, static tokens, completions, CI.
- WSL persistence: long-lived secrets (SSO sessions, bootstrap tokens) are also written to `~/.local/state/omnifob/vault/*.dpapi`, encrypted with Windows DPAPI for the current Windows user via `powershell.exe` (0.2 to 0.26 s per call). keyutils remains the fast cache. Simulated reboot (entries dropped from keyutils only): the real AWS session and Cloudflare bootstrap came back in about 190 ms, then 73 µs from keyutils. Cached credentials are not persisted (cheap to recreate).
- `fob status` showed "signed in until <yesterday>" for an expired but refreshable session; now "token renews on next use". Fetching credentials refreshed it silently overnight.
- Background renewal: credentials record `issued_at`; when less than a quarter of the lifetime plus the five-minute margin remains (20 minutes of a one-hour token), `fob` hands out the cached credentials and starts a detached `fob renew <profile>` (own process group, lock file per profile). Live: command with an aged Cloudflare token took 0.1 s, renewal finished in the background in about 6 s including the D1 wait, the next command used the new token and D1 accepted it.
- `fob revoke <profile>`: deletes the Cloudflare tokens minted for a profile (name prefix `omnifob:<profile>@`) and clears the cache; AWS only clears the cache. Live: deleted 3 leftover tokens.
- Generic `token` integration with 13 presets (hetzner, digitalocean, vultr, linode, upstash, akamai-edgegrid, scaleway, vercel, netlify, fly, neon, supabase, github): keychain storage, optional bearer check at login, one secret can fill several variables, non-secret `vars`, console URL. Not cached (read straight from the keychain). Live: bad Hetzner token rejected with Hetzner's 401; good and bad tokens against a local verify mock; Upstash with `vars`. A real GitHub token could not be used: the user's gh wrapper refuses `gh auth token`, rightly.
- Shell completions through clap_complete's dynamic engine (`COMPLETE=<shell> fob`): commands, flags, integration names and profile ids with the provider kind as a hint, read live from the profile cache. `fob activate` registers them along with the wrapper. `use` and `unuse` became real subcommands so they complete too; without the wrapper they print the activation line. Tested in fish (`complete -C`) and bash (calling the completion function); zsh is not installed here.
- `fob import aws [--file] [--write]`: finds IAM Identity Center portals in `~/.aws/config` (standard keys, `sso-session`, granted's `granted_sso_*`), normalises start URLs (case, trailing slash), names them after the session or subdomain, picks the most common profile region as `default_region`, skips portals already configured, and validates the result before writing. On the user's real file (685 sections): three portals, 439 and 16 profiles plus the one already configured. The real omnifob config was not changed; `--write` was tested on a copy.
- `--ttl` on env, exec, creds (and `fob use`): mints Cloudflare credentials with another lifetime, bypassing the cache read; refused with an explanation for AWS (permission-set session length) and static tokens. Live: `--ttl 3h` token expired three hours out; `0s` rejected.
